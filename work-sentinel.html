C 盘哨兵

一个常驻托盘的 Windows 小工具。当 C 盘莫名其妙少掉几个 G 的时候，它能告诉你时间、进程和目录。

类型
Windows 小工具
时间
2026 年 10 月
角色
独立开发
技术
Python · psutil · SQLite · pystray
5个功能页签：排行 / 膨胀 / 突发 / 历史 / 透视
5s默认采样间隔，可调到 2 秒
54MB常驻内存，整机 CPU 占用约 0.04%
30天数据自动清理，防止日志自己把盘占满

它回答三个问题

硬盘空间不会自己变少，但总有人在写。市面上讲「清理」的工具很多，讲「归因」的很少——所以这个工具不是一键清理，而是先把事情看清楚。

  • 现在是谁在写 C 盘？—— 按进程统计读写量，实时排序
  • 哪个文件夹在悄悄变大？—— 定期测量关注目录，算增长
  • 空间是一次性掉光的吗？—— 记录突发写入，留下时间戳

数据全部存在本地 SQLite 里，不上传任何地方，也不需要账号。

五个页签各管一件事

每个页签对应一个提问方式
进程排行本次运行以来每个进程累计写了多少、读了多少、当前速率。按写入量排序，冒头的就是嫌疑对象；双击某一行可在资源管理器里定位它的 exe。
目录膨胀把关注的目录（AppData、Downloads、ProgramData、Windows\Temp 等）每 30 分钟量一次体积。「较上次变化」列才是重点：红字正增长说明这个目录在长。
突发写入单次采样里某个进程写入超过 100 MB 就记一条。「空间突然少了好几个 G」的时刻，回这里找时间点。
历史查询按时间段汇总。程序关掉再开，数据还在——存在数据库里，CSV 按天滚动，可直接用 Excel 打开。
空间透视一次性体检：选路径、开始扫描，看哪个子目录最占地方。双击可下钻，一层层点到真正的元凶。

它自己占多少资源

监控工具最怕「监控本身成了负担」。所以后台线程跑在最低优先级，目录扫描做了限速（干一会儿歇一会儿），打游戏时基本无感。

本机实测（i7-13700H / 20 线程 / NVMe SSD）
平时挂后台约 0.8% 单核（整机 0.04%），内存 54 MB
目录扫描中约 58% 单核（整机 2.9%），每 30 分钟一次，持续 15–30 秒
数据库增长每天几 MB 到几十 MB，30 天自动清理

一个容易误解的点

「写入量」不等于「占用了多少空间」。进程写 500 MB，可能覆盖了旧文件、也可能只是一次性缓存，磁盘占用未必涨 500 MB。要看实际占用增长，得看「目录膨胀」页。

Windows 的 IO 计数器还包含管道、网络、设备写入，所以数字会偏大。它的价值在于相对排名：谁排第一，谁就是那个在折腾硬盘的。

什么样的增长算异常

正常情况下系统盘每天有几百 MB 到 1–2 GB 的读写波动（缓存、日志、缩略图、浏览器缓存）。真正要警惕的是三种：某个目录在你没做任何事的时候持续增长且不回落；同一个进程连续几小时霸占写入榜首；突发写入事件里出现你不认识的名字。

用到的东西

采集用 psutil 读进程 IO 计数器，界面是 tkinter + pystray 做托盘，存储用 SQLite，报告生成一份自包含的 HTML（不联网也能看，带每小时曲线、进程排行条形图、目录膨胀排行和突发事件表）。开机自启走当前用户注册表 Run 键，不需要管理员；想看到系统进程的写入才需要提权，界面上会明确提示这一点。
