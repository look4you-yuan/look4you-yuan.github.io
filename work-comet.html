彗星 Comet

六个页面，六颗星球，一台更轻的 Windows。无广告、免安装、全本地。

类型
Windows 桌面应用
时间
2026 年 10 月
角色
独立完成：设计 / 开发 / 打包 / 文档
技术
pywebview · WebView2 · 原生 JS · Python
12,152行自有代码（前端 + 后端 + 壳）
6页功能页面，每页一颗可转的星球
56个清理目标，六大类
29.9MB单文件免安装，双击即用

为什么还要再做一个清理工具

因为市面上的选择，要么在卖广告位，要么只敢扫最安全的三个目录。而这两年的电脑里，真正吃掉几十 GB 的东西早就换了一批：开发者缓存、浏览器 Code Cache、AI 工具留下的旧会话与本地模型。

传统清理软件没解决的四个问题
广告比垃圾多首页三块推荐位，点一次「一键加速」先给你装个全家桶。清理变成装机量的生意，不是解决问题的手艺。
只敢动最安全的地方Temp 和回收站之外一概不碰。npm / pip / Gradle / Docker 的缓存一放就是几十 GB。
AI 的痕迹没人管Claude Code、Codex、Cursor、豆包、Ollama 都在往 C 盘写缓存和旧会话，传统工具不认识这些目录。
卸完留一尾巴程序删了，AppData 里的同名目录、桌面快捷方式、注册表键全在原地，下次再装问题跟着回来。
所以它不叫「清理大师」。它不是帮你腾空间的工具，是让你知道空间去哪了的工具。

六个页面，每页一颗星球

每页一个主题色、一颗能用手拖动的星球。切页时背景交叉淡入，星球暂停自转、回来接着转。星球不是贴图——是手写的 GLSL 着色器做的球面交线、逐像素算法线、晨昏线与大气边缘光。

四层架构，没有一层是多余的

整套东西没有前端框架、没有构建步骤、没有网络字体、没有 node_modules。改一个类名刷新就见效——这是三天能改这么多轮的前提。

分层与代码量
UI5,427 行 —— index.html / style.css / app.js / planet.js，原生 JS，六页共用一个状态机
Bridgepywebview 的 JS API —— 前端只认 42 个具名方法，传 id 不传路径
Core3,356 行 —— paths / jobs / cleaner / aiclean / apps / appsize / updates / tune / diskmap / monitor
SystemWin32 / WMI / winget / 注册表 / SMART —— NtQuerySystemInformation 单次 15 ms 枚举进程
Shell675 行 —— 无边框窗口 + 自绘标题栏 + 托盘小彗星，PyInstaller onefile 打包

几个刻意的取舍

磁盘分析慢 60 秒是故意的。要秒级只能直接读 NTFS 的 MFT，需要管理员权限，还得处理压缩、硬链接、稀疏文件——三天里做不到不出错。于是选了「慢但精确」，并在界面上把秒数实时显示出来，让人知道它在干活。

前端只发 id，不传路径。路径映射留在后端的 CACHE 里，删除动作再过一遍白名单。就算前端被改，也删不到白名单之外的目录。System32、Program Files、驱动目录全程只读。

默认保守。需要管理员的项、正被占用的项、不可重建的项（模型权重、下载文件）默认不勾选；卸载与删除都要点两次；不可重建的东西走回收站，能捞回来。

手写着色器。three.js 要多带 600 KB，而这里只需要一颗球——120 行 GLSL 比引一个库更省事，也更可控。

本机实测

数据来自作者本机，不是演示数据
清出空间9.1 GB（其中 AI 痕迹 2.2 GB）
首次启动约 2 秒（要解压运行时），之后更快
清理扫描约 3 秒
软件枚举约 5 秒（201 项，带真实图标）
进程枚举15 毫秒
全盘分析约 60 秒（慢但精确，界面上有秒数）

打包成一个 exe 的代价是首启慢两秒，换来的是一句「双击就能用」。不写注册表、不常驻后台服务、不需要账号，不要了直接删掉 exe 就是卸载——这是我认为一个个人工具应有的样子。
